# 拾笺 · 家藏诗词

为家人的诗稿留一处安静的归所。Windows 优先，本地保存、本地 MinerU 识别，支持批量图片和 PDF、图文对照阅读、逐字校对与完整备份。

## 直接使用

在这台电脑，双击项目目录的 `start.cmd`，或 `release\current\Shijian\Shijian.exe`。启动入口优先使用更新版；旧目录 `release\Shijian` 可保留。升级后请先关闭已有窗口，再启动新版。

1. 点击「导入诗稿」，多选图片或选择整个文件夹，也可以直接拖入文件。
2. 选择诗集。导入只复制到本机，不会自动识别或上传文件。
3. 点击「开始本地识别」，任务会逐份运行。首次运行可能需要下载模型，耗时比日常识别长。
4. 打开诗稿，左边放大、旋转原图，右边校对文字。多页 PDF 可切换原稿页码，正文按整份文件保存。
5. 点击「保存并完成校对」。未完成的修改可「保存草稿」，Ctrl+S 也可保存草稿。
6. 收藏、按诗集归档，或搜索标题、作者、正文与札记。使用「静心阅读」专注赏读，也可切换竖排。

初次打开会展示六份**赏读示例**，用于体验界面。示例图片选自大都会艺术博物馆的公共领域馆藏，文字是独立搭配的预置古诗；图片并非这些诗的原稿，亦不是对图片的识别结果；它们不计入你的个人诗稿数量。

识别与阅读设置里有「长辈阅读模式」，会放大正文、诗稿标题及主要按钮。

## MinerU 是否适合手写诗稿

MinerU 是可用的本地文档识别起点。实际手稿可能有连笔、异体字、涂改、竖排、多首混排等问题，不能承诺自动得到准确的诗词版本。建议先用 10–20 页具有代表性的真实手稿试用「标准」和「精细」档，对比漏字、错字、行序及换行，再决定是否批量整理全部藏稿。

拾笺不调用语言模型润色，不把识别内容替换成网络上的通行诗句，不简繁转换。原图、MinerU 原始 Markdown、人工校对文字分别保存。新的识别结果统一进入待校对状态；重新识别已有文字前会提示，旧校对内容保存在历史中。原始识别文件与日志按每次识别分别留存。

本版本只实现本地识别，**没有 MinerU 云端上传接口或 Token 设置**。MinerU 首次使用会从 ModelScope（默认）或 Hugging Face 下载模型，这与上传诗稿不同。模型准备完成后，可以在设置中选择「仅使用已下载模型」；在所有所需模型都已缓存时使用。

目前接入 MinerU **4.0.7** 的 `mineru-kit parse`，默认 `standard`，强制扫描识别，关闭图片描述。逐个运行以避免并发耗尽内存。`basic` / `flash` 更适合印刷体预览；对手稿优先试 `standard` / `advanced`。

## Windows 分发与本地引擎

交付的 ZIP 解压后，保持整个 `Shijian` 文件夹完整，再运行 `Shijian.exe`。不要只复制 EXE：旁边的 `_internal` 包含运行依赖。应用使用 Windows WebView2；若桌面窗口初始化失败，会打开本机浏览器作为兼容方式。

软件与 OCR 引擎分开安装，避免把大型模型塞进每次软件更新包。

- 本次开发已安装引擎：`D:\py\.mineru\Scripts\mineru-kit.exe`，软件可自动发现。
- 新电脑：运行「安装本地识别引擎.cmd」。有随包附带的 `tools\uv.exe` 时，会自动创建 Python 3.12 环境；也可使用已安装的 uv 或 Python。
- 安装目标：`%LOCALAPPDATA%\Shijian\.mineru`，无需管理员权限。
- 如果自动查找失败，在设置中填写 `mineru-kit.exe` 的完整路径。
- 模型与运行配置：`%LOCALAPPDATA%\Shijian\mineru-local`；模型下载工具也可能使用用户级模型缓存。
- 模型体积为 GB 级，精细识别需要更多时间及内存。显卡兼容性依赖具体引擎；基础安装支持 CPU，未强制安装 CUDA / Torch。

安装脚本固定 MinerU 4.0.7。未来升级应先用样稿验证命令与输出格式。

## 数据与备份

默认诗库：`%LOCALAPPDATA%\Shijian\library`，与程序目录分离，更新程序不会覆盖诗稿。

| 内容 | 位置 |
| --- | --- |
| 原图 / 原始 PDF | `originals` |
| 缩略图与 PDF 分页预览 | `previews` |
| 每次识别的 ZIP 和日志 | `results` |
| 文字、诗集、收藏、校对历史 | `library.sqlite3` |
| 导出与备份的副本 | `exports` |

导出支持 TXT、Markdown、带原图和历史的档案 ZIP。整库备份使用 SQLite 的一致性备份接口，包含快照时的原图、缩略图、已结束的识别结果和数据库；不包含 Python 环境和模型。压缩期间可以继续读取和保存，后续修改进入下一份备份。正在写入的识别产物会跳过，并记录在 manifest.json 中；这些任务恢复后显示已中断，需重新开始。PDF 分页预览恢复后按需重新生成。

**恢复到新目录（推荐）：** 关闭拾笺，把备份解压到一个空文件夹，例如 `D:\家藏诗库`，创建一个启动用的 CMD：

```bat
@echo off
set "SHIJIAN_DATA_DIR=D:\家藏诗库"
start "" "D:\拾笺\Shijian.exe"
```

也可以在关闭软件、另行备份现有数据后，用备份内容替换原诗库目录。不要把旧数据库的 `-wal` / `-shm` 文件混入恢复目录。更换电脑后，如果设置中曾手动指定旧引擎路径，请在设置中清空路径以重新自动查找。

回收站采用软删除，可以恢复；当前版本不提供永久删除按钮。相同文件重新导入会去重；已在回收站的相同文件会恢复。请定期把备份 ZIP 复制到另外一块硬盘。

## 从源码运行

Git 仓库备份程序源码、界面素材、测试和安装脚本；个人诗稿、诗库数据库、识别结果、模型以及 Windows 构建产物不纳入版本控制。个人诗库请使用应用内「备份诗库」另行保存。

Python 3.12 或 3.13：

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe desktop.py
```

浏览器模式与自定义诗库：

```powershell
.venv\Scripts\python.exe desktop.py --browser --data-dir D:\家藏诗库
```

开发预览：`python desktop.py --server --port 8765 --data-dir .qa\library`。服务仅监听 `127.0.0.1`，不向局域网开放；写操作验证本机会话和请求来源。

打包：安装 `pyinstaller` 后运行 `build.ps1`，输出至 `release\current\Shijian`。可用 `-BuildOutput` 指定项目内的其他输出目录；构建会检查目标程序是否正在运行。

后端测试：安装 `pytest httpx`，运行 `python -m pytest -q`。前端回归测试使用 Node.js 内置测试运行器：`node --test tests/frontend.test.cjs`，无需额外前端依赖。

列表只返回短摘要，全文和札记搜索在本机数据库执行；画廊每页显示 48 份，批量全选和导出仍覆盖当前全部筛选结果。识别期间仅轮询任务摘要，有变更时刷新列表及未编辑的阅读页。保存期间会暂时锁定编辑区；保存失败会保留草稿，空正文不能标记为已校对。

## 验证范围与限制

- 自动测试覆盖原图保存、去重、回收恢复、繁体换行保真、历史版本、导出、整库备份恢复、多页 PDF、会话保护、队列取消与重试。
- 已用两张生成的印刷体《静夜思》PNG 实际完成导入、批量排队、MinerU 4.0.7 本地识别和文字回存；两份结果均进入待校对。首次端到端测试包含模型准备，约 89 秒。这项验证不代表手写字准确率。
- 每个文件是一份诗稿档案，多页正文合并保存；不会自动把一张纸上的多首诗拆成独立条目。
- 支持 JPG / JPEG、PNG、WEBP、BMP 和 PDF，每份不超过 200 MB、PDF 不超过 600 页。模糊照片、加密 PDF、损坏文件会报告错误。
- 画廊使用缩略图；对照阅读加载图片原文件或更清晰的 PDF 页面，支持放大与旋转。导出档案保留原始文件。
- 当前不包含手写置信度、自动定位疑似错字、朗读或跨设备同步。不会编造识别置信度或手稿内容。
- 未做代码签名；作为本地开发交付版本，程序行为和数据可通过源码核对。

## 项目结构

`desktop.py` 是桌面入口，`app.py` 提供本机接口，`storage.py` 管理 SQLite 与原稿，`engine.py` 负责 MinerU 队列，`static` 是无需前端构建的界面。
